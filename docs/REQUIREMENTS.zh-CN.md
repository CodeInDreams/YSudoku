# YSudoku 维护要求

本文记录产品与算法约束。换人或换 AI 维护时，先读本文，再改代码。
任何与本文冲突的实现都视为 bug。

## 1. 总原则

- 每一步必须能独立解释：根据什么规则、排除了什么、为什么。
- 不允许把后台搜索结果伪装成人类推理步骤。
- 正式步骤只接受**可见推导**：直接传播、明确规则、明确矛盾。
- 解不出来可以停在 `stuck`，但不能伪造结论。

## 2. 注意力与优先级

求解和反证都必须遵守“当前格/当前区域优先”，不是规则种类优先。

优先级从高到低：

1. 当前步涉及的 cell
2. 与当前 cell 同行、同列、同宫的区域
3. 候选更少的 cell
4. 收益更大的动作：
   - 落子优先于删候选
   - 能删更多候选的动作优先
5. 反证候选选择同样按当前 cell/区域，不按“稀有规则”加权

禁止：

- 因为 anti-king / anti-knight 稀有就优先选它
- 为了展示复杂规则而偏离当前区域

## 3. 反证与假设

- 假设前必须保存快照。
- 假设必须真实改变盘面，后续按正常步骤继续推理。
- 分支中的每一步都必须是真实动作，不能只写文字。
- 反证顺序：
  1. 反证开始：落假设
  2. 反证推理：执行真实传播
  3. 反证推翻：确认假设不成立
  4. 反证回退：恢复到假设前
  5. 反证结论：执行正式排除/落子
- 回退后必须用真实盘面重建 `expected`，不能把分支旧值补回去。
- 快照时点必须在假设落子之前。

## 4. 证据链

反证不能只给结论，必须从矛盾格反推证据链：

- 从“哪一格没有候选”开始
- 保留清空该格所需的最后一次删数
- 沿 `unit_peer` 的 by 格回溯
- 约束事件要把同一规则实例的参与格纳入
- 删除不在证据链上的格子的无关推理
- 不能删掉支撑后续结论的前置删数/落子

每一步必须能回答：

- 为什么这个候选被排除？
- 哪个规则/哪个已填格导致的？
- 参与格是谁？

禁止：

- “约束传播无解”这类空话
- 结论正确但依据缺失
- 依据使用裁剪后的候选，而事件来自完整上下文

失败原因要具体到：

- 哪个单元没有位置放哪个数字
- 或最后执行哪条规则后无解

## 5. 卡住判定

`stuck` 必须是真固定点：

1. 常规技巧无步骤
2. 候选缩小/子集/固定点检查
3. 仍无步骤时标出所有候选
4. 再重试
5. 所有约束都不能再改变任何候选，才是真卡住

只要能缩小范围，就不算卡住。

## 6. 候选与颜色

### 候选显示

- 候选不超过 6 个：用 Centre
- 超过 6 个：用叠层删除线表示

### 颜色语义

- 同色 = 同类
- 异色 = 异类
- 按类摒除候选
- 颜色不是题目公理，不能作为求解前提

### 调色板

- 禁用第一页前 3 个灰色
- 两格组：
  - 蓝 + 绿
  - 黄 + 橙
  - 红 + 紫
- 三格组：
  - 蓝 + 绿 + 紫
  - 红 + 黄 + 橙
- 不组合时使用色盘 4–9 任意分配
- 不够用第二页色盘
- 一个格子最多 4 种颜色

### 染色的来源

- 颜色是**联合约束推论的可视化**
- 算法先推出联合约束，再决定是否染色
- 手涂颜色不是输入公理，不能反过来证明结论
- 只有分类结构明显时才染色，不强行给所有步骤上色

## 7. 多规则交集

不能只逐条遍历规则。需要：

1. 以共享格构建局部交集组件
2. 把 V、颜色类、anti-knight、arrow 等放进同一组件
3. 在组件内检查候选是否有完整支持
4. 无支持才删除
5. 生成“联合约束”步骤，说明参与了哪些规则、联合推出什么

安全要求：

- 组件限制在 8–10 格
- 超预算/枚举不完时返回未知，不能返回“不支持”
- 交集删除必须通过独立安全闸
- 任何误删都要固化成回归测试

## 8. 测试

每段代码都必须有单元测试：

- 新规则/剪枝/启发式：聚焦单元测试
- bug 修复：先写会失败的回归测试
- UI 纯逻辑：单元测试
- 渲染：浏览器检查脚本

没有测试的改动不算完成。

运行：

```bash
python3 -m unittest discover -s tests
```

## 9. UI 约定

- 原始谜题链接显示在标题同一行右侧
- 新标签页打开
- 只读，不修改 SudokuPad 题目
- 支持上一步/下一步、实时渲染
- 不自动播放用户未点击的步骤

## 10. 禁止事项

- 隐藏穷举冒充推理
- 先有答案再补理由
- 用截图延迟解释逻辑错误
- 用规则稀有度替代当前区域优先级
- 把手工颜色当公理
- 无测试提交

## 11. SudokuPad 原生 Pen 语义

画线、圈、叉必须使用 SudokuPad 原生 Pen 工具，不得用 SVG 模拟。

Pen 工具入口：

- 设置中开启 `toolpen`
- 工具栏按钮 `#control-pen`
- 色板 `#control-colour`

行为：

- cell 点按：画圈 / 画叉 / 擦除，按当前状态循环
- 边界点按：画叉 / 擦除
- cell 中心拖动：连接 cell 中心，支持横、竖、斜 8 个方向
- cell 角上拖动：画线 / 擦除
- pen 颜色可选

颜色与目标已有颜色不同时：

- 点按类：循环状态不变，只刷新颜色
- 拖动类：自动变为擦除，直到抬笔

颜色约定：

- 确定：绿色
- 未定：橙色
- 否定：红色
- 使用第一页色盘，不用灰色前 3 个

多色格使用原生 `multicolour`，分界线为斜向，不得用 SVG 色块或竖向叠加模拟。
