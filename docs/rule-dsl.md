# 规则 DSL：让 LLM 安全地“自创规则”

这份文档说明为什么 **不能** 让 LLM 直接写求解代码，以及怎样在可验证的边界内让它
“看情况造规则”，以覆盖作者自定义的冷门规则。

## 1. 为什么不能直接执行模型生成的代码

- **不可判定**：模型生成的 Python 可以读文件、发网络请求、死循环；沙箱也挡不住逻辑错误。
- **不可信**：即使代码能跑，也无法证明它等价于规则文本。错误约束会让求解器“解出”一个
  不符合题意的答案，而且看起来非常合理。
- **不可解释**：我们的卖点是每一步都有可读理由；一段模型生成的代码无法自动变成中文解释。

所以 LLM 只能输出 **声明式 JSON**，执行语义由我们实现。

## 2. 三层能力

| 层 | 能力 | 状态 |
|---|---|---|
| **L1 重映射** | 规则文本 + 元素清单 → 已有约束类型的正确组合；卡住后带诊断信息重编译 | ✅ 已实现 |
| **L2 类型化组合** | 从固定原语（sum / count / ordered / distinct / region_count …）组合出新约束 | 📐 本文档 |
| **L3 插件代码** | 模型写 Python 插件 | ❌ 不做 |

L1 已经能解决大部分“规则看懂了但元素没对上”的问题（颜色、粗细、圆圈含义、XV/黑点混淆等），
并且完全不需要新代码。L2 才是“自创规则”的主体。

## 3. L2 的约束形状

```json
{
  "kind": "custom",
  "scope": {"element": "circle:3"},
  "predicate": {
    "op": "eq",
    "args": [
      {"op": "count_distinct_regions", "args": [{"var": 0}, {"var": 1}, {"var": 2}, {"var": 3}]},
      {"const": 3}
    ]
  },
  "cite": "Trisection circles: ... exactly three distinct regions",
  "hypothesis": true
}
```

- `scope`：元素 id 或显式格子列表，限定谓词的作用范围（≤ 6 格，保证可枚举）。
- `predicate`：类型化 AST，节点类型固定，见下。
- `cite`：规则文本中的依据片段；没有 cite 的规则直接拒绝。
- `hypothesis`：标记为“推测”，所有依赖它的步骤在 UI 里带徽章。

### 原语（第一批）

| 节点 | 语义 |
|---|---|
| `var i` | scope 中第 i 格的值 |
| `const k` | 常数 |
| `sum`, `min`, `max`, `abs` | 算术 |
| `count_digit(d)` | scope 中等于 d 的格数 |
| `count_distinct` | scope 中不同数字个数 |
| `count_regions` | scope 中不同区域个数（需要区域变量，P3） |
| `all_different` | 两两不同 |
| `ordered` | 严格递增 |
| `eq/ne/lt/le/gt/ge` | 比较 |
| `and/or/not` | 布尔组合 |

### 例子

**四格提示**（已有 `quadruple`，这里演示表达力）：

```json
{"kind":"custom","scope":{"element":"circle:0"},
 "predicate":{"op":"and","args":[
   {"op":"count_digit","args":[{"const":1}]},
   {"op":"count_digit","args":[{"const":9}]}]},
 "cite":"digits in the circle appear in the four surrounding cells"}
```

**“不平衡圆”**（1 或 4 个区域）：

```json
{"kind":"custom","scope":{"element":"circle:7"},
 "predicate":{"op":"or","args":[
   {"op":"eq","args":[{"op":"count_regions","args":[{"var":0},{"var":1},{"var":2},{"var":3}]},{"const":1}]},
   {"op":"eq","args":[{"op":"count_regions","args":[...]},{"const":4}]}]},
 "cite":"must either belong to the same region or four distinct regions"}
```

## 4. 传播与检查

- **枚举 GAC**：scope ≤ 5 时，枚举当前候选域的所有组合，逐值检查是否存在满足谓词的赋值；
  不支持的候选直接删除。9^4 = 6561 次谓词求值，可缓存。
- **专用传播器**：常见原语（sum / ordered / all_different）手写传播，避免枚举爆炸。
- **check(values)**：完整解上求值谓词，用于和官方答案比对、以及最终答案校验。
- **search**：同一个约束直接参与 DFS 的传播，保证唯一性检查与解释路径一致。

## 5. 可信性护栏

1. **不把答案给模型**。答案只在本地做三件事：拒绝违反它的规则、校验最终解、审计每一步。
   一旦模型看到答案，它就可以编一条“刚好等于答案”的规则，求解变成作弊。
2. **每条规则必须带 cite**，指向规则文本片段；UI 可展开查看。
3. **官方答案只做否证**：违反 ⇒ 直接拒绝；满足 ⇒ 只是必要条件，不代表规则正确。
4. **标注 hypothesis**：所有依赖推测规则的步骤加“推测”徽章，可一键关闭重算。
5. **双向验证**：若去掉推测规则后题目变成多解，而加上后唯一，说明规则“选了一个答案”，
   要显著警告（可能是过拟合）。
6. **审计分级**：反证审计只对“可信规则”断言；推测规则单独列出，不混入可信度统计。

## 6. 覆盖预期（诚实版）

| 题型 | L1 | L1+L2 | 备注 |
|---|---|---|---|
| 常见变体（杀手/温度计/点/线） | ✅ | ✅ | 主要靠 L1 |
| 作者自定义画法（颜色/圆圈含义） | ✅ | ✅ | L2 可表达大部分 |
| 四格提示、区域计数一类 | 部分 | ✅ | 需要区域变量时进入 P3 |
| 混沌构造 / 雾战 | ❌ | ❌ | 需要新的求解器（区域/可见性变量） |
| 依赖外部知识的规则 | ❌ | ❌ | 如“数字代表字母” |

**结论**：LLM 自创规则能把覆盖率从“常见变体”推到“作者自定义变体”，但推不到“任意难题”。
真正限制上限的是求解器能力（区域变量、可见性、搜索），不是规则表达。

## 7. 非目标

- 不做“让模型直接给答案”。
- 不做“模型生成可执行代码”。
- 不做“用答案反推规则”。
